## Runtime Defaults

- Human summaries are concise; JSON keys remain English.
- Use RTK for file/system inspection, not recon binaries.
- Recommendations come from `scripts/recommend.py` when Reporter loads it.
- Artifact interest comes from `scripts/artifact_interest.py` and deep download tools.
- Dashboard/console shows live analysis, pseudo-agent status, final summary, and RTK savings when `rtk gain` is available.
- Exposed interesting files are saved and reported by default.
- Suspicious readable text artifacts are reviewed by `artifact_analyze`, with raw secrets/proofs redacted in DB/UI/report.
- Report generation happens directly in `ReconOrchestrator.run()` through `Reporter`; there is no registered `generate_report` tool.

## Profile Flow

1. `port-surface`: full TCP discovery with `rustscan`, fallback `nc_scan`, then targeted `nmap`.
2. `web-surface`: `whatweb`, redirect/host handling, optional domain/vhost checks, `httpx`, headers, `cms_detect` pass 1, crawl, JS, fuzz, discovered-directory `curl_body`, `cms_detect` pass 2, artifact capture, and `nuclei_general`.
3. `js-hunter`: JavaScript dump, normalization, endpoint/secret/source-map/API mining.
4. `fuzz-hunter`: adaptive 6-second calibration, filter tuning, directory/recursive/extension expansion.
5. `api-hunter`: route/schema/parameter checks; current default worker uses `arjun`, while `kiterunner` remains registered but not wired into the default chain.
6. `service-surface`: matching `*_check` for non-web ports, currently deduped by global tool name rather than per-port action identity.
7. `ftp-hunter`, `smb-hunter`, `redis-hunter`: deep public/no-auth probes when supported.
8. `artifact-hunter`: classify, download, hash, index, and surface exposed files.
9. `report-writer`: documentation profile only; actual report is generated by `Reporter` after workers finish or max steps is reached.

## CMS / CVE Behavior

- `cms_detect` inspects root HTML, headers, cookies, meta generator tags, comments, assets, known marker paths, and fuzz-discovered paths.
- It detects common CMS/frameworks plus Pluck CMS markers such as `pluck-*`, `data/themes`, `styleadmin.css`, `login.php`, and meta generator strings.
- Directory URLs found by fuzz/crawl are fetched with `curl_body` before CMS pass 2 because CTF apps often hide real app roots in directory listings.
- Detected tech/service versions trigger generic `cve_search` with query shape `<name/service> <version> cve`.
- `cve_search` uses local `searchsploit --json`; reports only lookup evidence and never hardcodes writeup-specific CVEs.

## Suspicious Text Artifact Policy

Suspicious text-like files are mandatory review items. This includes `.txt`, `.log`, `.conf`, `.cfg`, `.ini`, `.env`, `.bak`, `.old`, and small text files with high-signal names such as `note`, `readme`, `todo`, `hint`, `backup`, `users`, `creds`, `credentials`, `password`, `secret`, `token`, `key`, `admin`, `config`, `db`, `database`, `dump`, `private`, `internal`, or `debug`.

Review content for credentials, usernames, emails, internal hosts/IPs/URLs, paths, database strings, commands, deployment notes, debug traces, private keys, hashes, JWTs, bearer tokens, cloud keys, and proof-like sensitive values. Redact raw sensitive values in dashboard/report; save raw content only in local artifact files.

## Service Checker

Generic usage:

```bash
python3 agent/skills/boot2root-recon/scripts/service_check.py smb --host 10.10.10.10 --port 445
```

Output uses simple key/value text for parser stability.

## Artifact Deep Tools

- `web_download_interesting`: downloads one high-signal web URL.
- `ftp_deep`: anonymous FTP recursive list and interesting file download.
- `smb_deep`: SMB null/guest share list and interesting file download.
- `redis_deep`: no-auth Redis metadata, key discovery, and capped value sampling.
